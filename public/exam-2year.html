Examination System Architecture Notice

1. Client-Side Security Limitations: In standard browser web applications, client-side JavaScript or localStorage alone cannot provide 100% tamper-proof proctoring against determined local inspection. Real-world high-stakes examinations require server-authoritative state, continuous biometric or webcam proctoring, and encrypted token session management.

2. Google Forms Cross-Origin Mechanics: Google Forms endpoints (/formResponse) are protected by cross-origin security headers. Client-side web pages cannot inspect response bodies directly due to the browser's Same-Origin Policy (SOP). The STDTech examination portal employs strict pre-submission schema enforcement, ensuring all 30 questions are answered with genuine form option strings before dispatch.

3. Recommended Backend Architecture: For institutional grading, we recommend configuring a secure Node.js server route (e.g., /api/submit-exam) that validates candidate session tokens on the server, signs the payload, submits to Google Forms or Cloud SQL database, and returns authoritative HTTP status codes.
